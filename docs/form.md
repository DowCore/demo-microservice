# 表单

表单是全局资产，资源和审批流按 `code` 引用。它描述单据长什么样，不负责把数据写进表。对标 Formily 的 Schema 运行时，以及 FcDesigner / VForm 的「设计器里预览、预览不写回 Schema」。

证据在 [表单契约](./detail/form-contract.md) §2.1、§4 的 F 系列、§5，以及 [预览规格](./detail/form-preview.md)。基线 `267d375`。

## 已实现

- 控件类型、容器树（栅格、卡片、明细、树）、`dependencies` 协议、`ColumnName`。
- 保存和发布时把布局拍平进 `Fields`。克隆保留规则、联动和控件配置。
- 发布校验字段名唯一；资源存在且有列时，与资源列对齐。
- 发布写入一份 `PublishedSchema` 和整数版本号。
- 删除前检查审批流、报表按钮和资源按钮是否引用。检查和删除不是原子的。

## 相对对标的不足

| 对标有的 | 本仓现状 |
|---|---|
| Formily / form-create 的字段规则在提交时求值 | `dependencies` 和字段规则只有协议。后端不求值 |
| 设计器内预览 | 没有表单预览 API。名为 preview 的接口是 DDL 或日期表达式 |
| 字段名和集合列在提交时映射 | `ColumnName`、`SubmitFlowKey` 没有执行期消费。资源提交走资源自己的 flowKey |
| 历史版本可回放 | 只有一份快照。快照为空时回落到可变草稿。抽出 0 个字段时不覆盖，已删字段可能还在 |
| 明细行的行级权限 | 明细结构能保存，行级权限和行联动没有 |

## 后续规划

| 优先级 | 事项 |
|---|---|
| P1 | 字段规则协议（必填、长度、正则、枚举）在提交时由服务端求值，不把校验只留在浏览器 |
| P1 | `ColumnName` 在资源写入时做字段名到列名的映射 |
| P1 | 拍平在布局抽不出字段时也要清掉旧字段 |
| P2 | 发布快照保留历史，空快照不再回落草稿 |
| P2 | 级联选项、异步选项。表达式求值若要做，必须是白名单函数，不能引入 eval |
| P3 | 子表行级权限、多语言、设计器按钮协议 |

明确不做：用表单 Schema 代替编排入参契约；在后端渲染页面。
