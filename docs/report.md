# 报表

报表是挂在资源或查询流上的查询页配方。对标 NocoBase 的 Filter Form 和 NocoDB 的条件组：普通人用表单和条件组筛选，后端收成一棵条件树。不对标积木报表的 Excel 画布。

证据在 [报表契约](./detail/report-contract.md) §2、§4、§5，以及 [配置器规格](./detail/report-config-ux.md)（前端未在本仓核验）。基线 `267d375`。契约 §4.3 把批量更新写成不可用，该项已在 `91d75bd` 修掉。

## 已实现

- `ReportDefinition` 的来源可以是资源、表或自定义 flow。
- `POST reports/{code}/query` 组装可见列、排序、汇总和数据范围，调用已发布的 `queryFlowKey`（默认 `sys.resource.query`）。未发布则拒绝。
- 条件树是运行时模型。编号组合式 `1 and (2 or 3)` 仍能编译，只作兼容。
- 同一资源可以有多份报表。列按 `Visible` 投影。

报表自己不生成 SQL。

## 相对对标的不足

| 对标有的 | 本仓现状 |
|---|---|
| NocoBase 的筛选表单、快捷筛选、统计卡在服务端生效 | `SearchForm`、`AdvancedFilter`、`Presets`、`Kpis` 只保存。关掉高级筛选也不会拒绝额外条件 |
| Amis / NocoBase 的按钮真正执行动作 | `ActionDef` 没有服务端执行端，也不校验批量上限 |
| 列权限和汇总字段由配方约束 | 请求里的 `columns`、`summaryFields` 可以超出设计器配置 |
| Metabase 的钻取、导出、保存「我的视图」 | 都没有。分组小计也没有 |
| 行级数据范围作用在查询上 | 直连 `sys.resource.query` 可以绕过报表权限和报表上的数据范围 |
| 积木报表的套打 | 明确不做 |

存储过程的结果会先全部读入内存再分页。

## 后续规划

| 优先级 | 事项 |
|---|---|
| P1 | 服务端强制：请求列 ⊆ 可见列，汇总字段 ⊆ 已配置列；`AdvancedFilter=false` 时拒绝表单以外的条件 |
| P1 | 查询表单字段子集、「任一满足」分组、快捷筛选芯片、KPI 统计卡 |
| P1 | 发布时登记菜单和 `App.Report.{code}` 权限。堵住直连系统查询流绕过报表授权 |
| P1 | 按当前筛选导出，列与可见列一致，设行数上限 |
| P2 | `ActionDef` 的服务端执行、分组小计、钻取到另一张报表 |
| P2 | 列样式用色调白名单；自定义渲染只返回描述符，不返回 HTML |
| P3 | 用户保存自己的列宽和默认筛选 |

明确不做：套打、交叉表、给业务员的即席 SQL。
